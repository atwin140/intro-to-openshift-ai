Reviewed Kubernetes reference for this demo:
- Pod status.phase is one of Pending, Running, Succeeded, Failed, Unknown. status.reason is a separate short explanation. A remaining node-pressure-evicted Pod has status.phase Failed and status.reason Evicted. Failed alone does not identify eviction. Evicted is not a Pod condition type. OOMKilled is normally a container termination reason, not interchangeable with pod eviction.
- Pod field selectors support status.phase, but not status.reason or status.conditions.type. When filtering a reason, retrieve JSON and filter client-side using jq or JSONPath. Do not invent server-side field selectors. Include namespace and pod name in cross-namespace output. Explain jq if used.
- For namespaced commands, -A lists all namespaces the caller is authorized to list, -n NAME selects a namespace, and neither flag means the current namespace. A list can show only Pod objects that still exist; it is not a historical eviction audit. A workload controller may create replacement Pods; it does not restart an evicted Pod object.
